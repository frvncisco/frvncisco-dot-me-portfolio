# Portfolio site (heyfrancisco.me)

Personal portfolio and blog. Started from the magicuidesign/portfolio template; much of the content is still template placeholder (see "Placeholder content").

Detailed, topic-specific guidance lives in `.claude/rules/`. Read those before changing the matching area.

## Commands

- Verification gate before calling work done: `format:check`, `tsc --noEmit`, `lint`, `pnpm test` (Node's built-in runner, pure lib code only), `pnpm audit`, then `build` with all flags on (`FEATURE_BLOG=true FEATURE_WORK=true FEATURE_CONTACT=true pnpm build`). `build` type-checks **every** file, including components nothing imports. On a fresh clone, run `build` or `dev` once before `tsc`, because `.content-collections/` is generated.
- Stop `next dev` before `next build` (they share `.next`).
- pnpm comes from corepack, pinned by `packageManager` (`pnpm@10.34.9`) in `package.json`. Without the pin, corepack falls back to pnpm 12, which the corepack in Node 24.2 can't run (`MODULE_NOT_FOUND .../bin/pnpm.cjs`). Put Node 24 on PATH first (`export PATH=~/.nvm/versions/node/v24.2.0/bin:$PATH`; `.nvmrc` is `24`). `.claude/launch.json` starts the dev server via `./node_modules/.bin/next dev`.

## Layout

- `src/data/resume.tsx`: the single content config (name, summary, skills, nav, social, work, education, projects).
- `src/lib/flags.ts`: feature flags. `src/lib/utils.ts`: `cn`, `formatDate`. `src/lib/og.tsx`: `renderOg`, the shared card for the three `opengraph-image` routes; its fonts and avatar are read from `public/` on disk (Node runtime) so they render without a live domain. `src/lib/posts.ts`: `getSortedPosts`. `src/lib/site-url.ts`: `siteUrl`, the base for every absolute URL (`SITE_URL`, then the preview URL, then localhost in dev, then `DATA.url`). Use it instead of `DATA.url` for links.
- `content/*.mdx`: blog posts, compiled by `content-collections.ts` (schema + `compileMDX`). `.content-collections/` is generated and gitignored; import via the `content-collections` alias.

## Conventions that are easy to get wrong

- **Feature flags**: `/blog`, `/work`, `/contact` are hidden unless `FEATURE_BLOG` / `FEATURE_WORK` / `FEATURE_CONTACT` equals `"true"`. Gated pages call `notFound()`; the nav hides the matching `DATA.navbar` entry (its `flag` field); `blog/[slug]` `generateStaticParams` returns `[]` when off. Flags are read at build time, so changing them on a host needs a redeploy. With `FEATURE_BLOG` off, the post `generateMetadata` returns nothing, and `/blog/opengraph-image` and `/blog/[slug]/opengraph-image` call `notFound()` (before calling `renderOg`, whose `try`/`catch` would turn the thrown `notFound()` into a 500), so hidden posts don't leak titles. The root `opengraph-image` isn't gated. See `.env.example`.
- **Fonts**: from the `geist` package, mapped in `@theme inline` in `globals.css`: `--font-sans` Geist Sans (body), `--font-serif` Fraunces, self-hosted from `public/fonts/Fraunces-Variable.woff2` so the build needs no network (all `h1`-`h6`, weight 600 and `h1`-`h3` at -0.02em from the base rule in `globals.css`, so don't set weight or tracking per heading; opsz, SOFT and WONK axes loaded, with the variation settings in `globals.css`), `--font-mono` Geist Mono (code), `--font-pixel-square` / `--font-pixel-line` Geist Pixel (special cases; `font-pixel-square`, `font-pixel-line`). OG cards read `public/fonts/Geist-Regular.ttf` and `Fraunces-Regular.ttf` (a static opsz 72 instance, since satori reads neither woff2 nor variable axes); Radix accordion headers are `<h3>` and are reset with `font-sans`.
- **Layout widths**: one container, tokens in `globals.css` (`--container` 80rem, `--gutter` 24/32/48px at base/`sm`/`lg`, `--measure-prose` 65ch, `--measure-sub` 36rem). `layout.tsx` adds only vertical padding; each page wraps its content in `<Container>` (`src/components/container.tsx`, `as="main"` for the page's `main`), and the fixed nav uses it too, so nav, headline and prose share one left edge. Everything is left-aligned on that edge, never centred. Reading pages (about, blog index, blog post, contact) put a `max-w-(--measure-prose)` column inside it; don't add `max-w-full` to `.prose` (it removes the 65ch cap). The hero headline has no max width of its own (type is `clamp()` per breakpoint) and the subtitle is 100% / 30rem / `--measure-sub`. The nav is only the pill of page links; social links live in the footer. The footer (`footer.tsx`, in `layout.tsx`, so on every page) is a three-card grid: a message card, a blue `--pixel-blue` mailto CTA to `DATA.contact.email`, and an icon row of the `DATA.contact.social` entries with `footer: true` (outline icons in `social-icons.tsx`, keyed by the social name). Wide content (the projects grid, up to 3 columns) uses the full container. A full-bleed element just doesn't use `Container`: backgrounds are `fixed`/`absolute inset-0` like the `FlickeringGrid`, and avoid `w-screen` (it overflows when a scrollbar shows). One-off measures in a component (`max-w-md` on the 404) are fine, but reuse a token before adding a new number.
- **Homepage**: a `DitherField` (Magic UI, WebGL2, `clouds` pattern) is the background of the hero `section` on `/` (`absolute inset-0`, not in the layout). The hero is full-bleed and `min-h-dvh`; `-mt-(--page-pt)` cancels the layout's top padding (`--page-pt` in `globals.css`, used by both) so it starts at the top of the page, and a CSS mask fades the sky into the white page background so sections below it start on plain white (they go inside `Container`, after the hero `section`). It is the page's sky: the peach base and the dot ramp are the `--sky*` tokens in `globals.css`. Muted grey fails contrast on it, so text over it uses foreground tints (`text-foreground/80` for the subtitle, `/70` for inactive nav links); re-measure contrast when you change the tokens, intensity or pattern. The pixel word in the headline is Geist Pixel Square with one `--pixel-*` colour per letter (supergroup.chat's hues, deepened to pass 3:1 on the sky and clouds). The hero fills exactly one screen at load; everything else, footer included, is below the fold. The field runs at up to 30fps and holds one frame under `prefers-reduced-motion` (`FlickeringGrid` is still used in the contact card); `MotionConfig reducedMotion="user"` (in `theme-provider.tsx`) drops `BlurFade`'s transform, and its `motion-reduce:filter-none!` class drops the blur (CSS, because the server can't know the preference and renders the blurred state).
- **Tailwind v4** is configured in CSS (`@import "tailwindcss"`, `@theme inline` in `globals.css`). There is no `tailwind.config.ts`; `components.json` still names one, which is stale.
- **Dark mode** (the `.dark` class via `next-themes`) is switched off: `ThemeProvider` in `layout.tsx` has `forcedTheme="light"` and there is no toggle (the old `ModeToggle` is in git history). The `.dark` styles stay for when it returns. Colors come from CSS variables; avoid hard-coded colors.
- **Pins**: `eslint` stays on 9.x (eslint-plugin-react crashes on 10) and `typescript` on 6.0.x (typescript-eslint needs <6.1). Don't bump without checking. `pnpm.overrides` forces patched versions of four transitive deps for security advisories. Each override is keyed on the vulnerable range (`pkg@<fixed`), not on a parent (see README "Tooling notes"); drop one once nothing resolves into its range. `@types/node` stays on ^24 to match `engines` and `.nvmrc`.
- `next.config.mjs` sends `X-Frame-Options: DENY`, so the site can't be loaded in an iframe.
- `next dev` regenerates the Next.js block in `AGENTS.md`/`CLAUDE.md`; leave them committed so the tree stays clean.

## Workflow

Plan first for anything beyond a small fix. Branch flow is feature branch to `dev` (staging) to `main`. See `.claude/rules/git-workflow.md`. Skills: `/commit` (conventional commits) and `/pr-review`. Review diffs with the `code-reviewer` agent. Always pass `-R frvncisco/frvncisco-dot-me-portfolio` to `gh` (extra remotes confuse its default repo).
